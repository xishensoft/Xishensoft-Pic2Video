# 票 02 选型：轻量预览编辑器 + 出片栈

- 日期：2026-11-22
- 机器：Windows 11 10.0.26200，系统 Python 3.12.5（C:\Program Files\Python312\python.exe），ffmpeg/ffprobe/ffplay 9.0.2（gyan.dev full build）
- 所有结论均在本机用命令实测；实测脚本在 ../probe/（perf_probe2.py、moviepy_probe.py、exact_probe.py、cmdlen_probe.py、web_probe.html 等），临时样片已清理。
- 说明：票面写的 E:\deepseek\FM1145 不存在，实际工作区是 E:\deepseek\FM114.5。

## 0. 结论（TL;DR）

**主选**：Python 3.12 单进程 **PyQt6** 桌面应用（本机已装 6.10.2，QtMultimedia 可用）+ **ffmpeg 单条 filter_complex** 出片；预览用 **先生成 540p preview.mp4，再用 QMediaPlayer 嵌入播放**。

**备选**：**tkinter**（标准库，零依赖）+ 同一套 ffmpeg 出片；预览改为生成 preview.mp4 后 **os.startfile / ffplay 外部播放**。UI 简陋但任何干净的 Python 都能跑。

不推荐把 MoviePy 当出片引擎（本机实测慢约 12 倍），也不推荐纯网页当主选（要自写 Range、交互和本地文件访问都更绕）。

一句话：**PyQt6 壳 + QMediaPlayer 播 540p 预览 + 一条 ffmpeg filter_complex 精确帧出 1080p30 H.264/AAC。**

### 本地网页方案可行性

- Edge 无头打开本地 HTML，video 指向 http://127.0.0.1:8765/sample_filter.mp4，结果：h264=probably、aac=probably、mp4=maybe、duration=6、err=null → **浏览器播本地 H.264/AAC 没问题**。
- 但 Python 3.12.5 的 python -m http.server（SimpleHTTPRequestHandler）**不支持 Range**：请求 Range: bytes=0-1023 返回 200 且无 Content-Range，等于整文件下载，大文件拖动进度会坏。官方文档里 http.server 也没提 Range。
- 要网页预览必须自写 Range 处理（ReelGeek 的 server.py 就是这么干的，约 30 行：解析 Range、206、Content-Range、Accept-Ranges）或引第三方 handler。
- 结论：网页方案可行但只适合当“无 GUI 依赖”的兜底；做桌面小工具不如 PyQt6 直接。

## 3. (b) 视频预览的真实选项

| 方案 | 实现代价 | 依赖 | 已知坑 | 本机实测 |
|---|---|---|---|---|
| PyQt6 QMediaPlayer + QVideoWidget | 低：setSource + play，seek 用 setPosition(ms) | PyQt6（已装） | 需要 Qt FFmpeg 后端（本机日志：Using Qt multimedia with FFmpeg version 7.1.2 LGPL）；QVideoWidget 要有父窗口布局；换文件时旧文件可能被占用；无逐帧精确 seek | 6s 样片 duration/position/状态全对；QVideoSink 2.2s 收 55 帧 1920x1080，取第 30 帧确认是 1s 画面（字母 A） |
| 低清 preview.mp4 + 系统默认播放器（os.startfile） | 最低：出片后直接打开 | 无（系统关联） | 外部窗口，App 拿不到播放进度；每改一次要重开；本机 .mp4 关联 WMP11，启动有延迟 | 540p 6s 预览生成 504ms / 113KB；可持续重生成 |
| ffplay 子进程 | 低：subprocess.Popen(["ffplay","-autoexit",...]) | ffmpeg 自带 | 独立窗口不嵌入；不随主窗口移动/关闭；要靠 -ss 定位；交互只有键盘（空格暂停、q 退出） | -autoexit -t 1 -x 640 -y 360 墙钟 1.75s，exit 0 |
| tkinter 内嵌视频 | 不可行 | 无原生控件 | 需要 PIL 逐帧 + Canvas 自己画，30fps 下 CPU 高、音画同步难；不值得 | — |
| 网页 video 标签 | 中：起 HTTP 服务 + 前端页面 | 浏览器 + 自写 Range | 见第 1 节：stdlib server 无 Range；本地文件需经服务端读 | Edge 解码 H.264/AAC 通过 |

**推荐做法（主选）**：编辑时只显示缩略图+时长；点“预览”时用同一套 filtergraph 以 960x540 / crf28 / preset veryfast 渲一个 preview.mp4（实测 6s 只要 0.5s），完成后 QMediaPlayer 载入播放。改动后 debounce 1s 重渲，写临时文件再原子替换，避免播放器占用。

关键片段（PyQt6）：

    from PyQt6.QtMultimedia import QMediaPlayer, QAudioOutput
    from PyQt6.QtMultimediaWidgets import QVideoWidget
    player = QMediaPlayer(self)
    audio = QAudioOutput(self)
    player.setAudioOutput(audio)
    video = QVideoWidget(self)
    player.setVideoOutput(video)
    player.setSource(QUrl.fromLocalFile(preview_path))
    player.play()

预览渲染（与出片同一 builder，只改尺寸/质量）：

    ffmpeg -y -loop 1 -framerate 30 -t D1 -i img1 ... -i bgm.mp3
      -filter_complex "<graph 里把 1920:1080 换成 960:540>" -map [vout] -map [aout]
      -c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p
      -c:a aac -b:a 128k -ar 48000 -ac 2 -movflags +faststart -shortest preview.mp4

（QUrl 从 PyQt6.QtCore 导入；预览和成片共用同一个 build_graph(items, W, H, fps)。）

## 5. (d) 合成路径对比（本机实测）

测试素材：3 张 1080p 图（A 横、B 横、C 竖 1080x1920），时长 2.0/2.5/1.5s，BGM 6s mp3，输出 1920x1080@30。

| 路径 | 6s 3 图耗时 | 输出 | 结论 |
|---|---|---|---|
| 单条 filter_complex（每图 split→模糊底+前景→overlay→fps/format→concat） | **1.06–1.20s** | 180 帧 / 6.000s / 136KB | **推荐**：一次解码一次编码，时长精确、无中间文件 |
| concat demuxer（每段先编码，再 -c copy 拼接） | 1.86s | 180 帧 / 6.000s / 133KB | 可用；必须每段 **-frames:v 精确帧数** 且编码参数完全一致；首版用 -t 2.5 得到 76 帧/2.533s，拼完只有 177 帧/5.9s（音画不同步） |
| MoviePy 2.2.1 | **15.09s** | 180 帧 / 6.000s / 129KB | 慢约 **12–14 倍**；每帧走 Python 回调，模糊底还得自己 PIL 预合成；依赖重 |
| 纯图片 concat 列表（file + duration 指令） | — | 90 帧/7.467s 或 224 帧/7.467s | **不可用**：ffmpeg 9 已无 -vsync，vfr/cfr 都拿不到 6.000s |

规模基准（20 图 × 3s = 60s，veryfast crf20，BGM 60s）：**10.35s 渲完，1800 帧，1,315,992 B**，约 5.8× 实时。按此外推 5 分钟片子约 1 分钟出头。

### 推荐命令（单条 filtergraph，精确到帧）

每张图：

    -loop 1 -framerate 30 -t <D+0.1> -i imgN

滤镜链（N = round(D*30)，用 trim=end_frame 锁定，避免 -t 多出 1 帧导致漂移）：

    [i:v]split=2[bg][fg];
    [bg]scale=1920:1080:force_original_aspect_ratio=increase,crop=1920:1080,
         gblur=sigma=40,eq=brightness=-0.08[bgx];
    [fg]scale=1920:1080:force_original_aspect_ratio=decrease[fgx];
    [bgx][fgx]overlay=(W-w)/2:(H-h)/2,setsar=1,fps=30,format=yuv420p,
         trim=start_frame=0:end_frame=N,setpts=PTS-STARTPTS[vN]

拼接与音频：

    [v0][v1]...[vK]concat=n=K:v=1:a=0[vout];
    [K:a]atrim=0:<total_frames/30>,asetpts=N/SR/TB[aout]

输出参数：

    -map [vout] -map [aout]
    -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -profile:v high
    -c:a aac -b:a 192k -ar 48000 -ac 2
    -movflags +faststart -shortest

图片循环铺满 BGM：先算 total = 音频时长；把图片序列按顺序重复到累计 ≥ total，最后一段用 trim 截断（实测 2 图×2s 重复成 4 段再 trim 6s：180 帧/6s，1.12s）。

大项目两条路（Windows 命令行上限 32767 字符，实测 40,435 字符时 subprocess 抛 OSError [WinError 206]）：

1. 滤镜图写文件：**-/filter_complex graph.txt**（ffmpeg 的 -/opt 语法，参数从文件读；本机 9.0.2 实测可行，引入见第 7 节 commit）。文件必须 **UTF-8 无 BOM**，PowerShell 的 Set-Content -Encoding UTF8 会带 BOM，触发 "Trailing garbage after a filter"；用 [IO.File]::WriteAllText + UTF8Encoding(false)。
2. 或按 ≤80 张分块，每块单独编码（-frames:v 精确帧数）再 concat demuxer -c copy，适合断点续渲和进度条。

注意：ffmpeg 9.0.2 **没有 -filter_complex_script**（Unrecognized option），也**没有 -vsync**。本机 20 图命令约 7,697 字符（≈385 字符/图），80–90 张就会接近上限。

颜色：输入是 jpg 时输出会被标成 yuvj420p(pc) 全范围；如果要严格 tv 范围，出片前加 scale=in_range=full:out_range=tv 或显式 -color_range tv，否则不同播放器可能偏灰/偏黑。

音频规范：本机 mp3 是 44.1kHz 单声道，AAC 输出也沿用了 44.1k 单声道（134kbps）；建议统一 -ar 48000 -ac 2，与仓库既有成品（AAC 192k）对齐。

## 6. 出片栈建议（一句话版）

- 编辑壳：PyQt6 单窗口（图片列表 QListWidget + 时长 QSpinBox + QMediaPlayer 预览 + 导出进度条）。
- 出片：后台线程 subprocess 调 ffmpeg，一条 filtergraph；参数集中在一个 build_command(items, audio, W, H, fps) 里，预览和成片共用，只换 scale/CRF/preset。
- 预览：540p crf28 veryfast，debounce 重渲，QMediaPlayer 播。
- 备选（无 Qt）：tkinter 同结构，预览 os.startfile 或 ffplay。

## 8. 风险与未决

1. **PyQt6 是 GPL-3**：自己用没事；一旦分发闭源就要商业授权或改用 PySide6-Addons（本机缺，需要装）。
2. **MoviePy 版本/依赖**：2.2.1 会拉 pillow<12、numpy，装到系统环境会跟 ultralytics 等打架（本机 pip 报了依赖冲突）；只能用隔离目录/虚拟环境。
3. **ffmpeg 9 的 CLI 变化**：-filter_complex_script、-vsync 都没了，网上大量旧教程会踩坑；-/filter_complex 对 BOM 敏感。
4. **时长精度**：不要用“-t + 图片 concat 列表”，一定用 trim=end_frame 或每段 -frames:v；否则 100 张图会累积几秒漂移。
5. **播放器占用文件**：QMediaPlayer 打开 preview.mp4 时 Windows 可能锁文件，重渲要写新临时文件再替换，并先 setSource(QUrl()) 释放。
6. **默认播放器不可控**：os.startfile 走 WMP11 关联，机器间可能不同；备选里最好直接调 ffplay 保证行为一致。
7. **色彩范围**：jpg 输入 → yuvj420p(pc)；成片建议显式 -color_range tv 或做范围转换后再交付。
8. **性能外推**：60s 10.35s 是纯 CPU veryfast；4K/慢盘/大量大图会变慢。硬件编码器（h264_nvenc/h264_qsv）在 PATH 的 ffmpeg 里存在，但本机未测，稳妥先用 libx264。
9. **音频规范**：现有 BGM 44.1k 单声道会原样进 AAC；要统一 48k 立体声需显式 -ar/-ac。
10. **大项目命令长度**：>80 张图必须切块或用 -/filter_complex，否则 Windows 直接报 WinError 206。
11. **竖图模糊底观感**：gblur sigma=40 + brightness=-0.08 是拍的，纯色图看不出模糊，真实照片需要再看一眼；可调 sigma/亮度。
12. **仓库成品是 AV1**：本编辑器先出 H.264（兼容性优先）；真要沿用仓库 AV1 规范，最后一步换 libsvtav1 重编即可，但会慢很多。
