# P2V 字幕功能改造方案

> 结论先行：P2V 现在能「导入 srt/ass → 烧录」，缺的不是烧录能力，而是**编辑**与**样式**两块。
> 本方案把字幕从「一条条时间戳 + 全局字体字号」升级成「可编辑的字幕块 + 一份可继承的样式表」，
> 并用 ffmpeg+libass 真渲做了像素级比对，证明预览与成片能对齐到 1~2 像素。
> 调研依据：[字幕工具工作流调研](./research/字幕工具工作流调研.md)；像素证据在
> [`docs/research/subtitle-style-parity/`](./research/subtitle-style-parity/)。

- README 明写「只做导入 + 烧录，不做应用内加字、改时间轴」——这正是本次要翻过去的一页。

### 1.3 与成熟字幕工具的五个差距

| 维度 | 通行做法 | P2V 现状 | 本方案 |
| --- | --- | --- | --- |
| 交互单位 | 「一句 = 一个可拖动的块」，拖两端定界 | 只能整块平移 | 五件套：双击改字、改入出点（数值框 + 拖两端）、新增/删除、播放头拆分/合并、整句挪 |
| 样式 | 命名样式表（Default 不可删）+ 块级覆盖圆点 | 一条写死的 Default | 默认样式表 + 每条只记差异（`overrides`） |
| 位置 | `F7` 拖位置 → `\pos`/`\an` | 写死底部居中、`MarginV=40` | 九宫格 + 按画面宽高百分比的边距，生成 `\an`/`\pos` |
| 所见即所得 | 预览与输出都是 libass | 预览 QPainter 一套、成片 libass 另一套 | 一份样式字典 → 两条渲染路径严格映射，实测偏差 ≤2px |
| 双语/打轴/AI | 有（且要联网 + 积分） | 无 | **不做**（见 §7） |

### 1.4 顺手挖出来的三个既有缺陷（本次实测，必须先修）

1. **烧录字幕比预览小 24%。** libass 把 Style 的 `Fontsize` 当作字体自身 `ascent+descent` 的高度来缩放字形，而预览用的是 `QFont.setPixelSize()`（em 框）。msyh 的 `(ascent+descent)/em = 1.32`，于是同一个 48 号，烧进成片只有 48/1.32 ≈ 36 px。实测比例 0.757 / 0.765 / 0.746 / 0.761，四个字号稳定在 0.75~0.76（`calib.json`）。
2. **`force_style` 会把样式表整行盖掉。** `ass_filter()` 传的 `force_style='FontName=…,FontSize=%d'`（`pic2video.py:2932-2939`）优先于 ASS 里的 Style，样式系统做了也不生效——这就是调研笔记里说的「卡点不在样式表而在三行代码」。
3. **`_ass_escape()` 会把 `{}` 转义掉。** 它把正文里的 `{` `}` 变成 `\{` `\}`（`pic2video.py:2725`），所以逐条覆盖的 `{\an7\pos(...)}` 这类前缀**不能**和正文一起转义，必须拼在前缀外面。

第 4 个是样式表里的坑：**libass 的 `BorderStyle=3` 用 `OutlineColour` 画框，不是 `BackColour`**；`Outline=0` 时框直接消失。真正的「底色框」要写 `BorderStyle=4`（实测 `box_probe2.py`：BS=3 → 红框=描边色，BS=4 → 绿框=底色，且框 = 文本宽 + 2×Outline、整块高 + 2×Outline，没有额外内边距）。

## 2 数据模型

### 2.1 字幕块（cue）

```python
def _cue(start, end, text, style="", overrides=None):
    """一条字幕：时间 + 文字 + 用哪套样式 + 与样式不同的那几个键。"""
    return {"start": float(start), "end": float(end), "text": str(text),
            "style": str(style or ""),          # "" = 用默认样式
            "overrides": dict(overrides or {})}  # 只记差异，空字典 = 完全跟随样式
```

- 沿用现有四键，**加一个 `overrides`**；`start/end/text` 语义不变，老代码（`_clean_cues`、`_sub_spans`、`cues_srt`、TTS 折行）全部继续可用。
- `style` 仍存样式**名字**：旧工程里从 .ass 读进来的 `"Default"` 或别的名字不会崩，只是名字不在样式表里时退回默认样式。
- `overrides` 的键必须是样式字典的子集（`STYLE_KEYS`），值按同一套取值域校验。

### 2.2 样式字典

一份样式就是 15 个键的扁平字典（纯 JSON，可直接进工程文件）：

```python
DEFAULT_SUBTITLE_STYLE = {
    "font": "Microsoft YaHei",
    "size": 48,              # 1080 高基准的 em 像素
    "bold": False, "italic": False,
    "primary": "#FFFFFF",    # 文字色 #RRGGBB
    "outline_color": "#000000", "outline": 2.5,   # 描边宽（px，1080 基准）
    "shadow_color": "#000000", "shadow": 0.0,     # 阴影偏移（px）
    "back_color": "#000000", "back_opacity": 0,   # 底色框，0 = 不画
    "align": 2,              # 九宫格 keypad 编号 1..9
    "margin_l": 3.1, "margin_r": 3.1, "margin_v": 3.7,  # 画面宽/高的百分比
}
```

默认值刻意对齐现状：老代码的 `MarginL/R=60`、`MarginV=40` 在 1920×1080 上就是 3.125% 与 3.7%，`Outline=2.5`、`Align=2` 原样保留。
设置页现有的 `subtitle_font` / `subtitle_size`（`pic2video.py:566-567`）变成默认样式的 `font` / `size` 两个字段，界面文案改成「默认字幕样式」。

### 2.3 工程文件升到 v3

```json
{ "version": 3,
  "subtitles": {
    "path": "…", // 导入来源，可选
    "cues":    [ {"start":0.0,"end":2.0,"text":"你好","style":"","overrides":{}} ],
    "styles":  { "Default": { …14 键… } },
    "default_style": "Default"
  } }
```

**迁移规则（v2 → v3）**：`cues` 原样读入、补 `overrides: {}`；`styles` 留空并要求宿主补种——因为默认样式来自**应用设置**，`Project.load_doc()` 拿不到设置，所以：

- `load_doc()` 读到 `version < 3` 时置 `self.styles = {}`、`self._styles_seeded = False`；
- 打开工程后由 App 调 `seed_default_style(project, settings)`，用设置里的字体/字号造出 `Default`，再 `_refresh_*`。

这样迁移不碰磁盘、不写坏旧文件，且可单测（见 §6 阶段 1 验收）。读入仍严格：版本号非 int / 大于 `PROJECT_VERSION` 照旧抛 `ProjectFileError`（`:1818-1824`），v3 只是把 `PROJECT_VERSION` 改成 3。

### 2.4 内存模型与撤销

- 样式合并只在**编辑发生时**做一次，结果缓存在 `self._effective_styles: dict[int, dict]`（cue 下标 → 生效样式），`reconfigure()` 与每次编辑后重建，绘制循环只查表，不重新合并。
- 撤销沿用现有快照机制 `_history_push(label)`（`pic2video.py:8572`）：每次编辑/拖动松手/改样式后 push 一次，标签用「改字幕文字」「改字幕时间」「改字幕样式」「拆字」「并字」。
- 时间线拖动过程中的中间态**不** push（与现有片段拖动一致），松手才 push。

## 3 交互细则

### 3.1 左侧「字幕」页升级成面板

布局（沿用现有 `sub_page` 位置，`pic2video.py:8946-8973`）：

```
┌ 字幕 ────────────────────────────┐
│ 已导入 12 条 · 来源 xxx.srt        │  ← lbl_subs（复用）
│ ┌──────────────────────────────┐ │
│ │ 00:01.0 → 00:03.5  第一句正文 │ │  ← 列表（可编辑文本）
│ │ 00:03.5 → 00:06.0  第二句正文 │ │
│ └──────────────────────────────┘ │
│ 时间 入 [00:01.000] 出 [00:03.500] │  ← 属性区 · 时间
│ 文字 [多行编辑框            ]     │  ← 属性区 · 文字
│ 样式：默认 ▾   (已改 2 项) [重置]  │  ← 属性区 · 样式
│   字体[▾] 字号[48] 粗 斜          │
│   颜色[■] 描边[■][2.5] 阴影[■][0]  │
│   底色[■][0%] 对齐[九宫格] 边距…   │
│ [＋新增] [－删除] [⇤拆分] [⇥合并]  │
│ [导入字幕…] [移除字幕] [另存 .srt…]│  ← 现有三键保留
└──────────────────────────────────┘
```

- 选中列表项 = 选中该字幕块：时间线高亮同一条，预览跳到该块起点（不打断播放）。
- 属性区永远作用于「当前选中这一条」；样式控件显示的是**生效值**，改哪个键就只把那个键写进 `overrides`，并在标题旁显示「已改 N 项」。
- 顶部「样式：默认 ▾」是这条字幕用哪套样式；「编辑默认样式…」按钮打开当前样式表的 `Default` 编辑器（同一组控件，改的是 settings 里的默认样式，所有未覆盖的条目立即跟随）。

### 3.2 双击改字

- 触发：列表项双击，或选中后按 `F2`。进入原地编辑（`QListWidget` 的可编辑 item），`Esc` 取消、`Enter` 提交、`Shift+Enter` 换行。
- 提交时：写回 `cue["text"]`（保留换行）→ `_refresh_subtitles()` → `_mark_dirty()` → `_history_push("改字幕文字")` → `_mark_stale()`。
- 空文本拒绝（提示「字幕不能是空的」，保持原样），首尾空白去掉；正文里的 `{` `}` 照旧由 `_ass_escape()` 保护。

### 3.3 改入出点（两个入口，一套规则）

**数值框**：属性区「入」「出」两个 `QDoubleSpinBox` 风格的 `mm:ss.mmm` 输入框，范围 `[0, total]`，步进 0.1 s。
**时间线拖两端**：字幕块左右各 6 px 热区，光标变左右箭头；拖动改对应端点，块本体拖动仍是整句挪。

统一规则：

1. **最短 0.1 s**：`end - start < 0.1` 时夹住（拖左端时 `start ≤ end - 0.1`）。
2. **吸附**：`SNAP_PX = 8`（`pic2video.py:2770`）换算成秒，候选点 = `snap_candidates()`（`:2783`，已含 0、总长、播放头、每个片段边界、音频与画中画首尾）**加上每条字幕的 start/end**（现在缺这一步，需要加 `extra=` 或在函数里补 cues）。
3. **不许重叠**：左端不越过前一条的 `end`，右端不越过后一条的 `start`——被夹住时光标下的数值框显示夹住后的真实值。
4. **后一条自动让位**：只在「把右端向右拉、跨过下一条 start」时发生——下一条整体右移同样的秒数（时长不变），并循环往后推，直到不重叠或到达片尾；到达片尾时改为夹住（不允许把别人挤出时间线）。左端拉伸不会导致让位（只夹自己）。
5. 松手 / 失焦 / 回车才提交：`_history_push("改字幕时间")`，标签与现有 `on_subtitle_move` 一致。

### 3.4 新增 / 删除

- **新增**（按钮或 `N`）：在播放头处建一条 `start = 播放头`、`end = 播放头 + 2.0 s`（沿用成熟工具里常见的「默认 2 秒」）的空块并选中、直接进入改字；`playhead + 2.0 > total` 时夹到片尾；与已有块重叠时起点顺延到下一个空隙，空隙不足 0.1 s 则不建并提示。
- **删除**（按钮或 `Delete`）：移除选中条目，选中移到相邻下一条。
- 两者都 `_mark_dirty()` + `_history_push`。

### 3.5 播放头拆分 / 合并

- **拆分**（按钮或 `S`）：要求播放头严格落在选中块内部（`start + 0.1 < t < end - 0.1`），否则提示「把播放头放到这条字幕中间」。拆成两段：`[start, t]` 与 `[t, end]`，**两段都保留原文**（要改哪段由用户双击改字），样式与覆盖两段都继承。
- **合并**（按钮或 `M`）：把选中块与**紧随其后的一条**合并：`end` 取后一条的 `end`，`text` 用换行连接两条（中间空一行？不——用单个换行，`_ass_escape()` 会写成 `\N`）。样式取前一条的，后一条的 `overrides` 丢弃并提示一句「已按前一条的样式合并」。

### 3.6 整句挪

保留现有拖动语义（`pic2video.py:6716-6729` → `on_subtitle_move()` `:10794-10803`），补三条：

1. 挪动时按同一套吸附点吸附起点与终点；
2. 落点若与相邻重叠，夹到相邻边界（`min(new, 下一条 start - 时长)`、`max(new, 上一条 end)`）；
3. 拖动中显示时间气泡（复用片段拖动的 `drop_guide` 风格）。

### 3.7 重新合成配音前的二选一

触发点：配音页点「生成旁白」且 `project.cues` 非空（无论来自 TTS 还是导入）。弹一次模态对话框：

```
重新合成配音会重排字幕时间。这次要怎么做？
  (•) 只换声音，保留现有字幕      ← 推荐，默认选中
  ( ) 声音和字幕一起换（按新旁白重新折行）
        [取消]  [继续]
```

- 选「保留字幕」：只更新 `narration_path/dur`，不动 `cues`；解说完的音频与已有字幕时间轴可能对不齐，底部状态栏给一条提示。
- 选「一起换」：走现有 `set_narration()`（`pic2video.py:2696`）折行逻辑，`cues` 被替换（旧 `overrides` 随之丢失，符合预期）。

### 3.9 手测清单（阶段 3 验收用）

1. 导入一份 12 条 srt，双击第 3 条改字，回车后预览与列表同步、时间线块内文字更新。
2. 拖第 3 条右端向左 1.5 s，前一条不受影响；再向右拉跨过第 4 条 start，第 4 条整体右移且时长不变。
3. 把播放头放在第 5 条中间按 `S`，得到两条且文字都在；再按 `M` 合回一条。
4. 播放头在片头按 `N`，出现 2 秒空块并进入编辑；连按两次 `N`，第二块顺延不重叠。
5. `Ctrl+Z` 逐步回退上述四步，每步都恢复原状（含让位的那一条）。
6. 选中一条，把描边改成红色 4 px，预览立即变红变粗；不打勾「重置」前，切换选中再回来仍是红色。
7. 把默认样式字号改成 36，所有未覆盖条目变小，覆盖过字号的第 6 条不变。
8. 对齐改成左上（7），边距 8%，预览与导出成片位置一致。
9. 底色框不透明度 100%，导出成片有实心框；预览框与成片框像素级对比差值 ≤2 px。
10. 另存 .srt 只有时间+文字；另存 .ass 带样式表与 `\an/\pos`。

## 4 样式参数表

### 4.1 参数 → 两个渲染器

| 键 | UI 控件 | ASS 落点 | QPainter 落点 | 取值域 | 默认 |
| --- | --- | --- | --- | --- | --- |
| `font` | 字体下拉（QFontComboBox） | `Fontname` | `QFont(family)` | 系统字体名 | Microsoft YaHei |
| `size` | 数字框（1080 基准） | `Fontsize = round(size × line_factor)` | `setPixelSize(round(size × h/1080))` | 16–160 | 48 |
| `bold` / `italic` | 两个勾选 | `Bold` / `Italic` = `-1` / `0` | `setBold()` / `setItalic()` | bool | False |
| `primary` | 颜色按钮 | `PrimaryColour` | `fillPath(color)` | `#RRGGBB` | `#FFFFFF` |
| `outline_color` | 颜色按钮 | `OutlineColour` | `QPen(color)` | `#RRGGBB` | `#000000` |
| `outline` | 数字框 | `Outline` | `QPen(width = 2 × outline)` | 0–20 | 2.5 |
| `shadow_color` | 颜色按钮 | `BackColour`（含 alpha） | 画偏移副本 / 暂不支持 | `#RRGGBB` | `#000000` |
| `shadow` | 数字框 | `Shadow` | 同上 | 0–20 | 0 |
| `back_color` | 颜色按钮 | `BackColour` | `fillRect` | `#RRGGBB` | `#000000` |
| `back_opacity` | 数字框 / 滑块 | `BackColour` 的 alpha + `BorderStyle=4` | `QColor.setAlphaF` | 0–100 | 0 |
| `align` | 九宫格按钮 | `Alignment` + `\an` | 锚点换算 | 1–9 | 2 |
| `margin_l` / `margin_r` | 数字框（%） | `MarginL/R` + `\pos` 的 x | 锚点换算 | 0–45 | 3.1 |
| `margin_v` | 数字框（%） | `MarginV` + `\pos` 的 y | 锚点换算 | 0–45 | 3.7 |

### 4.2 颜色：`#RRGGBB` ↔ ASS 的 `&HAABBGGRR`

```python
def ass_colour(hex_rgb, alpha=0):
    h = hex_rgb.lstrip("#")
    r, g, b = int(h[0:2], 16), int(h[2:4], 16), int(h[4:6], 16)
    return "&H%02X%02X%02X%02X" % (alpha, b, g, r)
```

- ASS 的 alpha 是**反的**：`00` = 完全不透明，`FF` = 全透明。底色框不透明度 `p` → `alpha = 255 - round(255 × p / 100)`。
- 只用 8 位十六进制（`&H00FFFFFF`），不用 `&HFFFFFF` 简写，避免 v4+ 解析歧义。

### 4.3 位置：九宫格 + 百分比边距 → `\an` + `\pos`

```python
def anchor_px(style, w, h):
    align = int(style["align"])            # ASS keypad：1-3 贴底、4-6 居中、7-9 贴顶
    col = (align - 1) % 3                   # 0 左 / 1 中 / 2 右
    row = 2 - (align - 1) // 3              # 0 顶 / 1 中 / 2 底（和 CSS 行序相反）
    x = w * style["margin_l"] / 100 if col == 0 else (
        w / 2 if col == 1 else w * (1 - style["margin_r"] / 100))
    y = h * style["margin_v"] / 100 if row == 0 else (
        h / 2 if row == 1 else h * (1 - style["margin_v"] / 100))
    return align, round(x), round(y)
```

**为什么要显式 `\pos`**：`MarginV` 只能表达贴底（和贴顶）的位置，中间一行（4/5/6）没法用边距表达；而且百分比边距要随成片分辨率换算。所以每条 Dialogue 都写 `{\an<n>\pos(x,y)}` 前缀，同时把等价像素值写进 Style 的 `MarginL/R/V` 作为兜底（第三方播放器忽略 override 时仍能落在合理位置）。

`\pos` 的锚点语义与 `\an` 一致：`an=1..3` 的 y 是文字块的**底边**，`4..6` 是**中线**，`7..9` 是**顶边**。QPainter 用同一个锚点算块的 top 即可（见 §5）。

### 4.4 字号与行高：`line_factor` 是这套方案的关键常数

```python
def line_factor(qfont):
    """字体自身 (ascent+descent)/em。libass 用这个高度解释 Fontsize。"""
    probe = QFont(qfont)
    probe.setPixelSize(1000)
    fm = QFontMetricsF(probe)
    return (fm.ascent() + fm.descent()) / 1000.0    # msyh ≈ 1.32

def ass_fontsize(px_em, factor):
    return max(1, int(round(px_em * factor)))
```

- `size` 一律按 **1080 高基准**的 em 像素存；成片/预览按 `size × 实际高 / 1080` 换算像素。
- 生成 ASS 时乘 `line_factor`；预览**不乘**（Qt 的 `setPixelSize` 就是 em）。两边因此字形一致。
- 行高：预览用 `ascent + descent`（**不是**现在的 `size × 1.25`，`pic2video.py:3709`），因为校准后 libass 的行高恰好等于 `Fontsize` = `size × line_factor`。
- `line_factor` 需要字体度量 → 放在 GUI 侧算一次、按字体名缓存；纯函数模块只接受数值 `factor`。

**取整零头要用 `\fscx/\fscy` 补回来。** ASS 的 `Fontsize` 只能是整数，所以 `round(size × factor)` 天然带误差：1080p、48 号、factor 1.32 时理论值是 63.36，只能写 63，实际 em 变成 63/1.32 = 47.7（差 0.6%）；540p 更糟，24 号算得 31.68 → 写 32，实际 em 32/1.32 = 24.2（差 1%，居中字幕因此整体右移 3 px）。

```python
def font_scale(style, height=1080, factor=1.0):
    """让 libass 的 em 精确等于 em_px 需要的缩放百分比（100 = 不用缩放）。"""
    em = em_px(style, height)
    size = ass_fontsize(em, factor)
    if size <= 0 or em <= 0:
        return 100.0
    return round(100.0 * em * factor / size, 1)
```

`dialogue_prefix()` 在 `\fs` 之后写 `\fscx<scale>\fscy<scale>`（与 100 差超过 0.05 才写），于是 libass 的等效 em = `size / factor × scale / 100`，正好等于 `em_px`。实测补完之后 540p 的 IoU 从 0.75 升到 0.87 以上（§5.3）。

⚠️ 这条补偿会让每一行 Dialogue 都带 `\fscx100.6\fscy100.6` 这类指令。它是**渲染层补救，不是样式差异**：断言「只有对齐变了、别的键不重复」时需要先把它剔掉再比。

### 4.5 底色框：`BorderStyle=4`

- 有底色（`back_opacity > 0`）→ `BorderStyle: 4`；否则 `BorderStyle: 1`。
- 实测 libass 的框 = 「文本宽度 + 2×Outline」×「行数×行高 + 2×Outline」，无额外内边距；QPainter 用同一公式 `fillRect`（`outline` 就是 padding）。
- 多行文本逐行画框（libass 的行为），预览照做。
- 为什么不用 BS=3：它用 `OutlineColour` 画框，`Outline=0` 时框消失（§1.4）。

### 4.6 ASS 生成与滤镜的三处改动

```python
# 1) format_ass：一个样式一行 Style，Dialog 带 override 前缀
"Style: %s,%s,%d,%s,%s,%s,%s,%d,%d,0,0,100,100,0,0,%d,%.1f,%.1f,%d,%d,%d,%d,1" % (
    name, st["font"], ass_fontsize(st["size"], factor),
    ass_colour(st["primary"]), ass_colour(st["primary"]),
    ass_colour(st["outline_color"]),
    ass_colour(st["back_color"], back_alpha),
    -1 if st["bold"] else 0, -1 if st["italic"] else 0,
    border_style, st["outline"], st["shadow"], st["align"],
    round(w * st["margin_l"] / 100), round(w * st["margin_r"] / 100),
    round(h * st["margin_v"] / 100))

# 2) Dialogue：前缀在 _ass_escape 外面拼
"Dialogue: 0,%s,%s,%s,,0,0,0,,{\\an%d\\pos(%d,%d)}%s%s" % (
    start, end, style_name, an, x, y, override_extra, _ass_escape(text))

# 3) ass_filter：去掉 force_style（它会盖掉样式表）
return "subtitles=filename=%s:fontsdir=%s" % (path, fontsdir)
```

- `override_extra` 只给「与 Style 不同」的那几个键：`\fs`（字号覆盖）、`\1c`、`\3c`、`\4c`（颜色，`&HBBGGRR&`）、`\bord`、`\b`、`\i`。位置**永远**写在前缀里，因为百分比要换算。
- `_write_ass()`（`:2912`）与 `_filter_path()`（`:2921`）不变；`ass_filter()` 只是把 `force_style` 参数删掉，调用点（`:10438-10440`、`:11844-11845`）同步去掉 `subtitle_font/subtitle_size` 两个实参。
- 字体找不到时仍由 `fontsdir` 兜底；导出计划里同样不再传 font/size。

### 5.2 映射对照（一张表看完两套渲染）

| 概念 | ASS | QPainter |
| --- | --- | --- |
| 字号 | `Fontsize = size × line_factor`（PlayResY = 成片高，故缩放比 1） | `setPixelSize(size × h / 1080)` |

### 5.4 残余差异与容差

| 差异 | 量级 | 处理 |
| --- | --- | --- |
| 字面渲染（hinting、抗锯齿） | 逐像素差，但不影响位置 | 预览侧统一 `QFont.HintingPreference.PreferNoHinting`（libass 走 harfbuzz 不做 hinting；不关的话 540p 下中文笔画被挤细、墨迹少 7%）；IoU 阈值仍定 0.85 |
| `Fontsize` 只能取整 | 1080p 约 0.6%、540p 约 1% 的整段缩放差 | 用 `\fscx/\fscy` 补偿（§4.4），补偿后 540p 的包围盒偏差 ≤2 px |
| 行高取整 | ≤1 px / 行 | 预览用浮点行高，只在落笔时取整 |
| 自动软折行 | 长句可能折行不同 | 第一批**只做硬换行**（`\N`），并在 UI 提示「一行太长请手动换行」；自动折行列为后续（见 §7） |
| 阴影 | `Shadow` 的偏移语义（= 偏移量，方向固定右下） | 第一批阴影只做「同向偏移副本」，不做方向可选 |
| 缺少字体 | 预览与成片会各自 fallback，可能不同 | 生成前比对 `QFontInfo(family).exactMatch()`，不匹配时提示换字体 |

**回归门槛**：`parity_probe.py` 作为发布前检查跑一次，三例 IoU 均 ≥0.85 且包围盒偏差 ≤2 px 才算通过。这条门槛同时能挡住「ffmpeg/libass 升级后字号语义变了」这类静默回归。

### 5.5 现有缺陷的修复判定

- 修之前：同一份 48 号白字，预览墨迹高 ≈ 45 px，烧录墨迹高 ≈ 34 px（比例 0.757）。
- 修之后：预览与烧录墨迹包围盒差 ≤2 px（§5.3 的 `bottom` 用例即此）。
- 这一条是阶段 1 的硬验收：**修完先把字号对平，再谈样式参数**。

## 8 风险与取舍

1. **`BorderStyle=4` 的兼容性**：libass 认它（实测），但 VSFilter 派生的老播放器可能把 BS=4 当描边。影响面只在「用户拿我们导出的 .ass 去别处用」；成片烧录由本机 libass 完成，无风险。取舍：烧录一律 BS=4；导出 .ass 时保留同样写法，并在 README 记一句差异。
2. **libass 字号语义依赖版本**：`line_factor` 是实测常数，ffmpeg 升级后可能变。用 `parity_probe.py` 做发布门槛，改动一处、三例全跑。
3. **预览渲染成本**：样式合并缓存 + 只在编辑时重建；描边路径每帧重画与现状同量级（本来就在画 `QPainterPath`），不引入 libass 到预览进程（那会多一个依赖与一条线程）。
4. **迁移不可逆**：工程一旦存成 v3，旧版 P2V 打不开（版本号更大 → `ProjectFileError("newer")`）。可接受：这是既有约定（`load_doc()` 的版本护栏），且 v3 只是多两个键。
5. **百分比边距的取整**：`\pos` 只接受整数，奇数分辨率会差半像素；统一在渲染时 `round()`，并在预览里用同一取整，避免「预览半像素、成片整数」。
