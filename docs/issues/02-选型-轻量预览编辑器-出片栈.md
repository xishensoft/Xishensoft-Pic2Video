# 02: 选型：轻量预览编辑器 + 出片栈

Type: research

Status: resolved
## Question

在 Windows + 已有 ffmpeg 9.0.2 + 系统 Python 3.12.5 的前提下，做一个“图片序列 + 一条音轨 → 视频”的小型可视化编辑器，最省的开源组合是什么？

要回答：
(a) GUI 框架：tkinter / PySide6 / 本地网页 哪个在**这台机器上当前就能跑**（列出已安装的包），谁有可用的视频预览控件；
(b) 预览播放的可行做法：窗内播放 / ffplay 子进程 / 生成低清试片交系统播放器，各自的实现代价与手感；
(c) 可直接借用的开源项目（MoviePy、ffmpeg-python、现成的 image-to-video GUI 等），能抄哪些最小交互，许可证是什么；
(d) 合成路径：concat demuxer / filter_complex / MoviePy，对“每张图不同时长 + 图片循环铺满 BGM + 竖图模糊底 + 1080p30”哪种最省、最稳。

产出：一条推荐方案 + 一条备选，含关键代码片段与出处链接；笔记写 `.scratch/pic2video/notes/选型.md`。

### local — 2026-11-22T13:58:13.359Z
选型定稿，完整笔记：`.scratch/pic2video/notes/选型.md`（实测记录、代码片段、出处链接都在里面）。

**主选**：PyQt6 单窗口 + QMediaPlayer 嵌窗播 540p 预览 + 一条 ffmpeg `filter_complex` 出 1080p30 H.264/AAC。
- PyQt6 6.10.2 本机已装，QtMultimedia 实测可播（6s 样片 position 走到 2298ms，QVideoSink 2.2s 收到 55 帧 1920x1080）。
- 合成实测：3 图 6s 用 1.06s；20 图 60s 用 10.35s（约 5.8× 实时）。每图 `split` → 背景 `gblur=sigma=40` 模糊铺底 → 前景缩放居中 `overlay` → `setsar=1,fps=30,format=yuv420p` → `trim=end_frame=N` 锁帧 → `concat`。
- 出片参数：`libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -profile:v high` + `aac 192k -ar 48000 -ac 2` + `-movflags +faststart -shortest`。

**备选**：tkinter（标准库，本机可开窗）+ 生成 540p 预览交 `os.startfile` 或 ffplay。

**关键事实**
- PySide6 只有 Essentials（`QtMultimedia` 导入失败）；PyQt5/wxPython 未装；网页方案可行但 `http.server` 不支持 Range，要自写。
- 纯图片 concat 列表在 ffmpeg 9 不可用；concat demuxer 必须每段 `-frames:v` 精确帧数，`-t` 会漂。
- ffmpeg 9.0.2 没有 `-filter_complex_script`、没有 `-vsync`；`-/filter_complex graph.txt` 可用但文件须 UTF-8 无 BOM。
- Windows 命令行上限：20 图约 7,697 字符，>80 图必须切块或走 `-/filter_complex`。
- 可借：ReelGeek（GPL-3，stdlib server + 自写 Range）、tanersener 脚本（MIT，模糊底）、videoshow（MIT）、MoviePy（MIT，但慢 12–14× 且依赖冲突）。
- 许可证：PyQt6 是 GPL-3/商业双授权；PySide6 是 LGPL-3；本工具只自用可接受，若要给人分发需注意。

选型已定：PyQt6 + QMediaPlayer + 单条 filter_complex，备选 tkinter。

选型结论已产出，笔记 .scratch/pic2video/notes/选型.md，主选 PyQt6 + 单条 ffmpeg filter_complex。
