## Question

用户 m05292：「优先修复闪退问题，为了方便以后修bug，创建个错误日志之类的措施」。追问时用户选了「记不清了，先把日志兜住」——所以这一票先把可查性做出来，不靠复现。

## Answer

全程日志落在 `%LOCALAPPDATA%\Pic2Video\crash.log`（源码运行也记，不再只管 exe）：

- `log(msg)`：时间 + 线程 + 内容，逐行 flush；写日志本身出错一律吞掉。
- `_start_log()`：每次启动写一行版本头（`Pic2Video 1.1.0`）+ frozen/argv/python/平台/cwd/settings 路径；超过 1 MB 轮转成 `crash.log.1`；窗口版 exe 的 stdout/stderr 挂到这份文件；`faulthandler.enable(all_threads=True)` 抓段错误；`sys.excepthook`（三参）与 `threading.excepthook` 把未捕获异常连 traceback 写进去；`qInstallMessageHandler` 把 Qt 警告也收进来。
- 面包屑：启动/窗口显示/关闭、主题、设置打开与保存、加图/删图/改时长/换位、时间线拖时长与换位、音频增删/换位/音量、淡入淡出、右键菜单、拖放、取音轨开始与结果、预览开始/成功/失败、导出路径与参数/成功/失败。
- 设置 → 其它 → 「错误日志」显示路径 + 「打开日志」按钮（explorer /select），旁边加「版本」行。

**顺手修掉一个真 bug**：`sys.excepthook` 原来写成两参 lambda，真崩溃时 Python 只报 `Error in sys.excepthook: lambda() takes 2 positional arguments but 3 were given`，把原始 traceback 一起吞掉——正是「闪退查不出原因」。现在是 `lambda _t, exc, tb`。

验证：
- 冒烟跑完日志里能看到完整链路（apply_theme → window show → add_images×3 → preview start/ok → export start/ok → window close）。
- `PIC2VIDEO_SHOT_CRASH=1` 故意在 Qt 回调里抛 `RuntimeError`：日志里出现 `!!! uncaught sys` 与完整栈（`RuntimeError: crash probe: uncaught in Qt slot`），窗口随后正常退出。
