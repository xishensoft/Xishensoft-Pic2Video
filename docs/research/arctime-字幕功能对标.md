# ARCTIME Pro 字幕功能对标

> 研究对象：Arctime Pro 4.5（Windows 桌面版）的字幕工作流，用于回答「P2V 的字幕功能该往哪里长」。
> 证据截止：2026-11。来源全部是官方页面：主站 <https://arctime.org/> 与镜像 <https://arctime.cn/>（同站同文，正文逐页比对过；下文统一引 arctime.org 链接）。产品营销页 <https://arctime.pro/> 只用于版本与卖点，功能细节以教程页/更新记录为准。
> 版本口径：页面不标版本时按 2026-11 在线版（4.5，2025-02-26 发布）；功能引入版本以 [更新记录](https://arctime.org/changelog.html) 为准；包内附带的 4.5 版 PDF 用户手册未见在线版，本笔记**未**引用其内容（未验证）。
> 引文规则：引号内是官方页面原文照抄（含原有空格与标点），未改写成自己的话；无法在官方页找到出处的说法标「未验证」。
> 本站页面正文夹有站长辱骂竞品的粗口注入行，与功能无关，本笔记不引用、不转述。

**一句话结论：Arctime 真正值钱的不是「能加字幕」，而是把「一句字幕 = 一个可拖拽的块」做成了唯一交互单位——建块（回车/拍打/拖拽/标记/VAD）、定界（拖边缘 + `[` `]` + 3/4 键）、批量（多选 + 对齐 + 消隙）、样式（命名样式表 + 小组）全部围绕这个块收敛，再靠「ASS 即预览即输出」保证所见即所得。P2V 已有 cue 数据模型、波形峰值和 snap 候选，抄它的**交互骨架**便宜；要抄它的**样式系统与所见即所得**，必须先解决两件事：P2V 的应用内预览是 QPainter 手画而不是 libass，`force_style` 又把字体字号钉死——这两处不改，抄来的样式只会「导出好看、预览不对」。**

## 怎么读这份笔记

- **三档判断**（口径按任务书）：**便宜**＝纯 UI/数据模型，不动渲染与输出；**中等**＝要改 ASS 生成、滤镜参数或新增一个渲染通道；**贵**＝要引入新依赖、云服务、AI 或账号体系。
- **两个渲染落点**单独标：`libass`（`subtitles` 滤镜，能吃 ASS override 代码 `{...}`）与 `ffmpeg filtergraph`（只能靠滤镜参数，如 `drawtext`/`overlay`）。凡是要「一句话里多种颜色、逐字动画、精确定位」的，几乎都必须走 libass override。
- **P2V 现状锚点**（判断依据，全部来自 `pic2video.py`）：一条顺序 `filter_complex`（`build_graph()` `pic2video.py:926`）；字幕走 `subtitles` 滤镜（`ass_filter()` `pic2video.py:2932-2939`），生成器 `format_ass()` `pic2video.py:2739` 只写**一行** `Style: Default`；预览却是 QPainter 自己画（`_draw_subtitles()` `pic2video.py:3703-3726`），只认全局字体/字号；字幕面板是只读文本列表（`_refresh_subtitles()` `pic2video.py:9664-9679`），时间线只能整块平移（`on_subtitle_move()` `pic2video.py:10794-10803`）。
- 表里「P2V 落点」给到函数名与行号，方便直接开票；行号是 2026-11 的工作副本。

## 1. 全流程：一条字幕从建工程到压出画面

Arctime 的流程是「**媒体 → 文稿 → 时间轴（块）→ 样式 → 输出**」，每一段都有独立面板，且任意一段都可以跳过。

| 阶段 | 它提供什么 | 入口 / 按键 | P2V 现状 | 档位 |
|---|---|---|---|---|
| 建工程 | 新建/打开 `.atpj` 工程；`Ctrl+I` 导入音视频（已有媒体时变为**替换**媒体）；自动备份默认开启、默认 5 分钟一次，可查看备份文件 | `Ctrl+N` / `Ctrl+O` / `Ctrl+I`，备份在 [首选项](https://arctime.org/preference-settings.html)、[FAQ](https://arctime.org/help.html) | 工程 JSON 已存 cues 与设置（`pic2video.py:1803`） | 便宜 |
| 文稿（可选） | 右侧「内容面板」直接粘贴/编辑未打轴文稿；「铅笔」图标开高级文本编辑器，可「查找、批量断句、替换、正则替换、快速合并、检查每行字数」 | [文本面板](https://arctime.org/content-panel-and-text-processing.html) | 无文稿概念，只有已解析的 cue 列表 | 便宜 |
| 建块 | 回车插空白块（默认 2 秒）；右键插入；`Alt`+鼠标选区；快速创建模式拖拽或 J/K 拍打；由标记批量生成；VAD 自动切分 | 见 §2 | 只能从 .srt/.ass 导入 | 便宜 |
| 打轴 | 波形 + 频谱、吸附开关、块边缘拖拽、`[` `]` 定界、3/4 键、批量对齐 | 见 §2 | 只能整块平移 | 便宜～中等 |
| 编辑 | 双击改字、多选、复制粘贴、合并切分、文字修剪、查找、重叠处理 | 见 §3 | 无 | 便宜 |
| 样式 | 命名样式表（Default 不可删）+ 7 个小组 + 块级独立参数 + ASS 代码透传 | 见 §4 | 只有全局字体/字号两项 | 中等 |
| 双语/翻译 | 双语稿切双轨；翻译器逐句；批量机器翻译（积分） | 见 §5 | 无 | 中等 / 贵（机器翻译） |
| 预览 | **用 ASS 渲染预览**，即「Arctime使用ASS格式来输出并预览字幕」 | [ASS 输出模式](https://arctime.org/ass-encoding-mode.html) | QPainter 手画，与导出不一致 | 中等～贵 |
| 压制/导出 | 标准 MP4（x264/x265，CRF 推荐、ABR 可选）；MKV 直接封装 ASS；专业格式与「可关闭字幕流」需特权；字幕另存 ASS/SRT/VTT/LRC/XML/PNG 等 | `Ctrl+R` 标准压制、`Ctrl+Shift+R` 高级压制、`Ctrl+E` 导出字幕，[压制说明](https://arctime.org/hard-burn-subtitle.html)、[输出格式](https://arctime.org/export-formats.html) | 已有导出链，`format_ass` + `subtitles` 烧录 | 便宜～中等 |

**流程上的两个设计决定值得注意**：其一，文稿与时间轴是**两条独立的数据**，文稿可以晚于时间轴存在，靠「填充」把文字灌进已建好的块（`Alt+↓`）——所以「先打空轴、再补文字」是官方推荐路径，多人协作也建立在这个拆分上（[协作](https://arctime.org/cooperation-via-atpj-files.html)）。其二，**预览与输出共用 ASS**，没有第二套渲染器，因此样式编辑器里看到的就是导出结果——这条正是 P2V 目前缺的。

## 2. 打轴交互：它最核心的东西

### 2.1 三种标记与「什么区间会变成块」

标记是 Arctime 打轴的底层原语，字幕块可以由标记推导出来（`F8`），也可以只当视觉标记用。

| 类型 | 快捷键 | 用途 |
|---|---|---|
| 开始标记（开始点） | `,` | 标记字幕块开始 |
| 普通标记（标准点） | `;` 或 `M` | 「既可以标记字幕的开始或结束，也可以当做普通视觉标记」 |
| 结束标记（结束点） | `'` | 标记字幕块结束 |

操作规则（官方原文归纳，[时间轴标记](https://arctime.org/use-timeline-marker.html)）：

- 「每个时间点只允许存在一个标记」；同种标记重复插入＝删除，插入另一种＝切换类型。
- 标记可左右拖动改位置，「按住标记点向上拖拽一段距离可以快速删除标记点」。
- `Alt+[` / `Alt+]` 跳上/下一个标记；`F7` 预览「哪些区间会产生有效的字幕块」。
- 建块判定只有一句：「凡是结束点后面跟着开始点的区间，都是无效的，不会创建字幕块，其他情况都会创建。」——换句话说，块是「开始…结束」的有向配对，普通标记按其前后类型解释。
- VAD 自动切分产出的正是标记而不是块：「自动切分之后，会在时间轴创建一系列标记点，而不是直接创建字幕块。」（[自动切分音频](https://arctime.org/auto-voice-activity-detection.html)）目的是让人**先调标记、再一键成块**，避免返工。

> 值得抄的抽象：P2V 现在只有 cue，没有标记。「标记 → 块」这个两级结构让「粗打轴」和「定稿」可以分开做，也让 VAD 这类自动结果有一个可人工修正的中间态。

### 2.2 快捷键：按「你在调什么」分组

全部取自官方 [键盘快捷键](https://arctime.org/keyboard-shortcuts.html) 页（时间轴面板/字幕块/编辑框三节），只摘与打轴编辑相关的。

**(a) 播放与导航**

| 按键 | 发生什么 |
|---|---|
| `Space` | 播放 / 暂停 |
| `[` `]` | 不播放时跳上/下一个时间节点；播放时前后快进 2 秒，按住 `Shift` 5 秒 |
| `Alt+[` `Alt+]` | 跳上/下一个标记点 |
| `←` `→` | 暂停时播放头微调 1 像素（`Shift` 10 像素）；播放时时间轴滚屏 25% |
| `+` `-` | 时间轴前后滚屏 75% 宽度 |
| 大写锁定 | 临时启用时间轴实时滚动 |
| `` ` `` | 让时间码进入编辑状态（见 2.5） |
| `↑` `↓` | 切换选中轨道 |
| `W` | 快速放大鼠标所在区域 |
| `F` | 切换「一句话预览是否跟随鼠标」 |
| `P` | 音频实时预览开关（鼠标在时间轴滑动即试听） |

**(b) 建块**

| 按键 | 发生什么 |
|---|---|
| `Enter` | 在播放头插入空白块，**默认 2 秒**（时长可在选项面板改） |
| `Shift+Enter` | 插块并「使用文本区域的第一条符合条件的内容填充」 |
| `D` | 切到拖拽创建工具（拖出一段即成块） |
| `J` / `K` | 拍打：按住定开始、松开定结束；J、K 交替按住＝连续建块 |
| `T` | 双用：① 把两块的衔接点设到播放头（要求播放头在 A 的 50% 之后、B 的 50% 之前）；② 播放头右侧无块时，按下即「设定左边字幕块的结束时间，同时在该位置创建一个新的字幕块」 |
| `Ctrl+Enter`（编辑框内） | 「确认编辑，并在下方新建等宽字幕块」——等同「沿用这一条的时长再建一条」，是「重复上一条时间」在官方文档里唯一对应的操作；`Alt+Enter` 则把光标后的文字转到下方新建的等宽块 |
| `F8` / `Shift+F8` | 依标记批量生成空白块 / 生成并依次填入文稿内容（页内自注「不推荐」） |
| VAD | 自动切分音频 → 得到标记 → 再成块 |

拍打（tap）是它区别于「拖拽」的关键手感：**跟着播放用按键记时**，而不是事后拖。产品页把打轴卖点写成「手动可拖拽、按键拍打」「精确的波形图参考」（[Arctime Pro](https://arctime.org/arctime-pro.html)）。所谓「按拍子抓取」在官方页里**没有**对应功能名，能找到的只有「拍打」与波形对齐（未验证：是否存在节拍/BPM 吸附，官方页未见记载）。

**(c) 定界与切分**

| 按键 | 发生什么 |
|---|---|
| 拖块左右边缘 | 改入点/出点，时长变化 |
| `[` / `]` | 「设定字幕块开始时间、结束时间」到播放头 |
| `3` / `4` | 快速设定开始 / 结束时间，作用于「播放头穿过或右侧第一个」「播放头穿过或左侧第一个」块，**不需要先选中** |
| `C` | 切到切割工具（点一下即切） |
| `1` / `2` | 按住 = 文字向前/向后修剪：切分后把切分点前的文字移到前/后一句，同时「两句话的时间轴衔接点也会被设为当前播放头所在的位置」 |
| `5` / `6` | 文字向上/向下修剪，「只对含有绑定关系的字幕块有效」 |
| `B` | 绑定工具：在块上拉线建立绑定；同轨两块直接绑定＝合并 |
| `Alt`+单击时间轴 | 快速切分空白块（4.5 更新记录） |
| `S` | 开关吸附 |

**(d) 搬移、多选、批量**

| 按键 | 发生什么 |
|---|---|
| 拖动块 | 平移，时长不变；按住 `Shift` 锁定左右只上下挪轨 |
| `←` `→` | 移动 1 像素（`Shift` 10 像素） |
| `Ctrl+Shift+↑↓` | 上移/下移一轨 |
| `Ctrl+A` / `Ctrl+Shift+A` / `Ctrl+Alt+A` | 全选 / 选中当前轨道全部 / 选中全部空白块 |
| 框选、`Shift` 增选减选、`Tab` 下一个、`Esc` 取消 | 多选 |
| `A`（已是选择工具时） | 选中播放头所在块；`Shift+A` 只保留当前轨道的高亮块 |
| `Ctrl+[` | 「将所有选中字幕块作为一个整体，左侧移动到播放头位置（长度不变）」 |
| `Ctrl+Shift+[` `]` | 移动所有选中块左/右侧对齐到播放头，长度不变 |
| `Alt+[` `]` | 调整所有选中块的边界，长度变化 |
| `Alt`+拖右侧块 | 多选状态下批量联动长度 |
| `Ctrl+L` | 「消除多个字幕块之间的间隙，使其首尾相连」 |

### 2.3 吸附与波形对齐

- `S` 开关吸附；首选项里可「提供默认不开启吸附」。
- 波形图与频谱图精度在首选项中可调（「默认『常规』适用于绝大多数要求……若电脑配置较低，调高此项可能会造成界面卡顿」），改后需重新加载媒体生效（[首选项](https://arctime.org/preference-settings.html)）。
- 对齐靠「看波形 + 拖 + 吸附」，没有「对齐到音频事件」这种自动量；多人协作页把分工写成「B负责将粗略的时间轴调整到与波形精确对齐」，说明精度判断仍以人眼读波形为主（[协作](https://arctime.org/cooperation-via-atpj-files.html)）。

### 2.4 自动切分音频（VAD）：唯一离线可用的「自动」

算法是**门限 + 卷积**，四个参数（[自动切分音频](https://arctime.org/auto-voice-activity-detection.html)）：先定门限（「大于视为语音」，用于滤底噪与背景音乐），再设「最短静音时长」与「最短语音时长」决定粒度，最后设「语音提前量、延长量」给前后呼吸空间。入口：主菜单 ► 语音识别 ► 自动切分音频（高级）。4.2 起最短语音时长上限改为 5000 毫秒。

限制写得很直白：「只适用于纯人声或仅轻微背景音乐」；结果只与音频特征相关、**与文稿无关**，不能直接填文稿。

> 这是全站少数「自动」但**不联网、不扣积分**的能力——对 P2V 的意义比 ASR 大得多。

### 2.5 时间码输入（`` ` `` 键）

「让时间码进入编辑状态，可快速进行时间跳转」，支持（[键盘快捷键](https://arctime.org/keyboard-shortcuts.html)）：

| 输入 | 结果 |
|---|---|
| `` ` `` 后回车 | 跳到视频开头；再按 `` ` `` 回车跳末尾 |
| `50` / `50s` | 50 秒；`1h`、`1m`、`100ms` 同理 |
| `1m5s`、`1h6m`、`1h6m30s` | 复合单位（复合单位不支持 `+-` 前缀） |
| `+5`、`-1:20` | 相对当前位置前后跳 |
| `a` / `z` | 跳到当前（或多个选中块中的第一个/最后一个）块位置（4.5） |

4.3 起时间码支持小数。这套「一段文本解析成时间偏移」的输入，比拖播放头精确得多，是硬字幕对轴的刚需。

### 2.6 批量调整（错位修复）

选中块后「鼠标左右拖即可批量调整」，或按 `F1` 打开时间调整工具（[批量调整](https://arctime.org/batch-edit-subtitles.html)）。它把日常的对轴错误分成 6 类，每类一个开关式操作：整体提前/延迟、整体压缩、整体拉伸、部分偏移、部分压缩或拉伸、混合。

这套面板的存在说明一件事：**打轴的成本大头不是「打第一遍」，而是「改第二遍」**——整轨偏移几十毫秒、片头加了 3 秒导致全轨平移，都是常态。P2V 现在只能一句一句拖，这一块是纯 UI 收益。

## 3. 字幕块的编辑

| 能力 | 怎么做 | 细节 / 按键 | 来源 |
|---|---|---|---|
| 改文字 | 双击块进入编辑；选中后按 `Enter` 同样进入编辑 | `Enter` 确认并退出，`Esc` 放弃；`F5` 在编辑态播放这句音频 | [上手指南](https://arctime.org/quick-start-guide.html) |

| 上下标 | 编辑框内按住 `Alt` 展开上标/下标快捷输入面板 | 4.0 起 | 同上 / [更新记录](https://arctime.org/changelog.html) |

### 4.2 三种「花活」其实是 ASS 特性的直通

| 效果 | 操作 | 实现口径 |

| 一句多样式 | 「由于Arctime是基于ASS渲染的，所以呢也支持ASS的效果代码」，用**样式替换代码**：`{\r ? } xxxxx {\r}`，`?` 为指派样式名 | `\r<StyleName>` |
| 进度条 + 章节 | 双击标记输入备注作为章节标题；≥2 个带备注标记；用自带 `BarFX` 样式控制外观（字体颜色/字号＝标题，描边颜色＝上层色，阴影颜色＝底色，垂直边距同时影响标题距底边与进度条厚度）；输出时自动在视频旁生成 `xxx-chapters.txt` | 样式 + `\pos`/`\p` 一类绘制 |

词汇过滤有个重要限定：「该功能仅对使用Arctime直接输出视频或输出ass字幕有效。」——即它是一层**输出期变换**，不改工程里的原文。这个「原稿与输出分离」的思路值得借鉴（[特殊字幕效果](https://arctime.org/subtitle-special-effect.html)）。

### 4.3 ASS 输出模式：同一份时间轴，四种落法

这是全站技术含量最高的一页，也最容易被忽略：「Arctime使用ASS格式来输出并预览字幕」，输出提供 A/B/C/D 四种算法（[ASS 输出模式](https://arctime.org/ass-encoding-mode.html)）：

| 模式 | 行为（原文要点） | 适用 |
|---|---|---|
| A 向下合并 | 默认；「适合标准单语/双语」，但块之间可能互相影响 | 最省事 |
| B 保持轨道结构 | 「每个字幕块的断点不会影响到其他字幕块。但是字幕块在轨道中的位置决定了在屏幕中显示的位置，一个轨道相当于一行，放在最下面轨道的字幕块在最后一行。」 | 多轨/双语 |
| C 保持字幕块独立 | 默认；块互不影响且**轨道位置不影响显示位置**（轨道更像图层，重叠时上面轨道的块显示在上方）；「不会自动换行，需上移一行可在末尾加 \N」 | 需要精确控制 |
| D 保持顶级字幕块独立 | 正文仅「建设中」 | — |

> 对 P2V 的直接含义：**双语不需要新渲染器**，只需要「两条轨道 + 两个 Style + 合适的 Alignment/MarginV」，或者干脆走模式 B 让轨道＝行。真正需要 override 的只有「同一句里换样式/换位置/做动画」。

### 4.4 样式系统的成本真相

它的样式系统之所以「便宜」，是因为预览和输出都交给 libass，样式表就是 ASS；P2V 的预览是 QPainter（`_draw_subtitles()` `pic2video.py:3703-3726`，只读 `subtitle_font`/`subtitle_size`，取 `_plain_cue()` 纯文本），导出才是 libass。因此 P2V 做多样式必须二选一：

1. **预览侧补一套「ASS 样式子集 → QPainter」映射**（字体/字号/颜色/描边/阴影/对齐/边距/位置）。中等工作量，能覆盖 90% 日常样式；`\r`、`\t`、`\move`、`\p` 这类不覆盖，预览里显示为纯文本（可接受，但要提示）。
2. **预览也走 libass**（ffmpeg 单帧渲染或 libass 绑定）。所见即所得最彻底，但每帧起进程不可行，绑定 libass 是**新依赖**（贵），且 `subtitles` 滤镜是烧进画面的，做不了「预览关字幕」。

不管走哪条，都得先改两处：`ass_filter()` 里的 `force_style='FontName=…,FontSize=…'`（`pic2video.py:2932-2939`）会把样式表里的字体字号**盖掉**，做多样式时必须去掉；`_ass_escape()`（`pic2video.py:2725`）把 `{`/`}` 转义成 `\{` `\}`，写 override 前必须先让它放行合法代码块。

## 6. 依赖边界：哪些必须联网、登录或花钱

P2V 是离线优先、无账号的桌面工具，所以这一节直接决定「抄不抄」。

| 功能 | 依赖 | 官方原文 / 口径 | 离线等价物 |
|---|---|---|---|
| 建块、打轴、波形、样式、特效、双语切分、拼音、自动换行、词汇过滤、压制、导出 | **纯本地** | — | 无差异 |
| 自动切分音频（VAD） | **纯本地** | 门限+卷积四参数 | 无差异 |
| 单句语音识别 | 联网 + 登录 + 积分 | 「语音识别属于 按量付费 功能，需要联网并登陆使用」；识别失败不计费，重复识别重复扣费 | 自建 whisper.cpp（模型体积大，贵）或不做 |
| 全自动整段语音识别（转写） | 联网 + 登录 + 积分 | 「语音转写属于 按量付费 功能，需要联网并登陆使用」；任务「一旦成功创建…便不可取消」，成功即扣费 | 同上；P2V 的 TTS 已有网络通道但方向相反 |
| 自动打轴（AI） | 登录 + 积分 | 「要使用自动打轴，首先要登录Arctime账号，并确保积分充足。」 | 只有 VAD（精度不同） |
| 语音合成（TTS） | 积分（部分引擎还需密钥） | 「语音合成 1 积分 7 字符」；语音数据不嵌入工程，存 `Temp Audio/工程ID` | P2V 已走 Edge/Gemini/OpenAI 兼容（`tts_engine.py`） |
| 批量机器翻译 | 联网 + 积分 | 70 字符 1 积分 | 无（本地翻译模型体积/质量都不划算） |
| 高级压制/专业格式/软字幕导出 | 登录 + **特权**（激活制） | 软字幕导出特权 10000 积分终身、专业格式 36000 积分终身；「激活制将于2025年中停止…仅能够跟随资源卡权益」 | ffmpeg 直接给（P2V 天然免费） |
| 单机离线版 | 付费买断 | 两项特权打包 500 元；且「这些功能不可用：自动打轴、语音识别、语音合成、机器翻译、登录、注册、检查更新。」 | P2V 全面覆盖其离线部分 |
| 局域网总控服务器 | 付费 | 约 8.8 万/年起 | 不适用 |

**结论**：Arctime 的功能面里，**打轴/样式/双语/导出这些「骨架」全是离线的**，联网项集中在识别、翻译、合成三件事，且都以「积分」计价。这恰好说明 P2V 抄骨架没有依赖风险；一旦要碰 ASR/翻译，就必须自己做本地模型或接受联网，不能假装是「免费离线功能」。

| 18 | 词汇过滤（输出期淡化/替换） | 便宜 | 只在烧录前改文本，不影响工程原文 | `_write_ass()` `2912` 前 | 生成侧 |
| 19 | 额外导出格式：VTT / LRC / MicroDVD / Excel | 便宜 | 全是文本序列化 | 与 `cues_srt` 并列 | 无 |
| 20 | MKV 直接封装 ASS、可关闭字幕流 | 便宜 | `-c:s copy` / `-c:s ass` + 封装参数 | 导出命令 | filtergraph/封装 |
| 21 | 导出带 Alpha 的纯字幕 MOV、PNG 序列 | 中等 | 要逐句渲染成图（ffmpeg 单帧 + libass） | 新导出分支 | **libass 渲染** |
| 22 | VAD 自动切分（产出标记） | 中等 | 算法 50 行 + 复用已有峰值；纯离线 | `audio_peaks` `1583`、`WAVE_RATE` `1528` | 无 |
| 23 | 自动备份 / 撤销重做 | 便宜 | 撤销已有（`on_subtitle_move` 就打的撤销点） | 已有 | 无 |
| 24 | `xxx-chapters.txt` / 输出目录约定 | 便宜 | 纯文件旁产物 | 导出链 | 无 |
| 25 | AI 打轴 / ASR / 转写 / 机器翻译 / TTS 云端 | 贵 | 联网 + 账号 + 积分；P2V 无账号体系 | — | 云 |
| 26 | 导出到 9 种非编（XML/PRTL/ETL/DS Cap/AE） | 贵 | 每种一套私有 schema，维护成本高，且 P2V 定位是成片 | — | 无 |
| 27 | atpj 工程交换协作（合并文本/导入分轴/导入样式） | 贵 | 要定义可合并的工程格式与冲突规则 | — | 无 |

**只在 libass（`subtitles` 滤镜）里成立**：一句多样式 `\r`、独立位置 `\pos`、打字机/滚动、进度条绘制、带 Alpha 的纯字幕 MOV。P2V 已经走这条路（`ass_filter` → `subtitles`），所以这些**不需要新依赖**，只要生成正确的 ASS 文本并让 libass 吃到。

**只能改 ffmpeg filtergraph/命令**：封装与流选择（MKV 装 ASS、可关闭字幕流、CRF/ABR/H.265）、烧录开关、逐句渲图（PNG 序列/Alpha MOV）。这些不涉及 ASS 内容，是命令行参数问题。

**必须绕开的位置**：`force_style`（会盖掉样式表）与 `_ass_escape`（会吃掉 override）——这两处不先处理，上面所有 override 类方案都会「看着写了但没生效」。

## 8. 值得 P2V 抄的 10 条

| # | 抄什么 | 为什么 | 档 |
|---|---|---|---|
| 1 | 一句 = 一个块，块有 in/out/文字/style/track；`Enter` 插空白块、默认 2 秒 | 所有编辑动作都收敛到一个对象上，是后面所有功能的公共底座 | 便宜 |
| 2 | 拖边缘改 in/out + `[` `]` + `3`/`4` 键定界到播放头 | 打轴 80% 的时间花在定界，鼠标拖与键盘定界必须并存 | 便宜 |
| 3 | `` ` `` 时间码输入（`1h6m30s`/`+5`/`a`/`z`） | 精修几十毫秒靠拖是自虐，文本输入才可复现、可批量 | 便宜 |
| 4 | 吸附开关 + 吸附候选含播放头/块边界/音频头尾 | P2V 已有 `snap_candidates`，只差把 cue 边界也塞进去 | 便宜 |
| 5 | 三种标记 + 「开始…结束」建块规则 + `F7` 预览 | 「先粗打轴再定稿」的两级结构，也让 VAD 结果有可人工修正的中间态 | 便宜 |
| 6 | `J`/`K` 拍打 + 拖拽创建模式（跟播放计时，而不是事后拖） | 听写场景的正确手感，比「先插块再拖」少一半操作 | 便宜 |
| 7 | 多选批量：整体平移/压缩/拉伸、`Ctrl+L` 消隙、`Alt` 联动长度、`F1` 面板 | 打轴返工的大头是整轨偏移，这是一次性投入长期回本 | 便宜 |
| 8 | 命名样式表 + 每块 `style` 字段 + 小组颜色 | cue 已有 `style` 键，只缺 `format_ass()` 写多行 `Style:`；不引入新依赖就能做「多条样式」 | 中等 |
| 9 | 双语双轨：双语稿隔行切分 + `Alt+↓` 逐行填充 + 第二语言独立样式 | 双语是刚需，且不需要新渲染器（两条 Dialogue 或轨道＝行） | 中等 |
| 10 | 文稿↔块 文本流转：`Ctrl+C` 导出块文本、`Ctrl+V` 逐行填充、`Ctrl+U` 合并、`F3` 并入下一行（快速创建工具下） | 翻译、重排、错句修复全靠这套，比「一块一块改」快一个数量级 | 便宜 |

## 9. 明确不该抄的 5 条

| # | 不抄什么 | 为什么 |
|---|---|---|
| 1 | 积分制 + 账号登录 + 特权激活 | P2V 的口碑建立在「离线、无账号」；把核心能力挂到积分上等于换产品。官方自己都要靠「单机离线版 500 元买断」来兜底，说明这套对离线党不成立 |
| 2 | AI 自动打轴 / 语音识别 / 整段转写 / 批量机器翻译 | 全部「按量付费、需联网登录」，且转写「一旦成功创建便不可取消、成功即扣费」；识别后仍要人工校对，收益/成本比在 P2V 里不划算 |
| 3 | 导出到 9 种非编的私有 XML（PRTL/ETL/DS Cap/Pro Import AE…） | 每套 schema 都要长期跟版本；P2V 的出口是成片，不是给非编接力。真需要时「ASS + PNG 序列」两条够用 |
| 4 | 进度条 BarFX / 词汇过滤 / 卡拉OK 逐字上色 | 平台合规与花活，靠 ASS override 堆出来的特例样式；P2V 1.x 没有这类需求来源，做了只会变成维护负担 |
| 5 | 四套 ASS 输出模式全做（A/B/C/D） | 官方自己把 D 写成「建设中」、C 与 A 又都标「默认」，说明连它也没收敛；P2V 固定一种（双轨时按轨道＝行）即可，别把四选一暴露给用户 |

## 11. 未验证 / 存疑

1. **按拍子（BPM）抓取**：官方页只有「拍打」（J/K/T）与波形对齐，未找到节拍检测或 BPM 吸附的功能名与说明——本笔记按「不存在于官方文档」处理。
2. **4.5 版 PDF 手册**：包内附带但未在线获取，本笔记未引用其任何内容。
3. **拍打精度**：官方未给按键与播放头之间的延迟指标；P2V 若做拍打，实际抖动需自测。
4. **`F7` 两处含义**：字幕块上的 `F7` 是「调整字幕定位」（快捷键页），标记页的 `F7` 是「预览标记生成的块」；两页分属不同焦点上下文，本笔记按页面分别引用，未验证是否真的是同键不同上下文。
5. **`F4` 两处含义**：快捷键页「字幕块 `F4`＝设定特效」，另有「`F4` 在几个主面板之间依次切换」；同上按上下文区分。
6. **「等宽块」的确切含义**：`Ctrl+Enter` 的「等宽字幕块」，官方只写了「等宽」，未定义是等时长还是等轨道宽度；本笔记按「沿用这一条时长」理解。
7. **MKV 与特权的关系**：输出格式页把 MKV（原始视频+音频+ASS 直封）列为常规视频输出，压制页却把「MOV/TS/FLV/MKV 封装」列进需特权的「高级压制」，两页口径不一致，未验证实际归属。
8. **次级来源**：网上教程/下载站常把 Arctime 说成「自动打轴神器」「一键成片」，与官方页面口径（识别后仍需校对、按量计费）不符，本笔记未采用。
