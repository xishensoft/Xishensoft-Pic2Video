# 字幕工作流调研：专业桌面字幕工具的通行做法

> 目的：回答「P2V 的字幕功能该往哪里长」。写法上只记录**功能存在性与操作方式**这类事实，全部用自己的话转述，不复制对方正文、不使用对方截图。
> 调研时间：2026-11。方法：阅读该工具官方站点的教程页、快捷键页、更新记录与定价页（链接集中在文末「来源与版权说明」），逐页核对功能是否真实存在、依赖什么。
> 判断口径：**便宜**＝纯 UI 或数据模型，不动渲染与输出；**中等**＝要改 ASS 生成、滤镜参数或新增一条渲染通道；**贵**＝要引入新依赖、云服务、AI 或账号体系。
> 两个渲染落点单独标：`libass`（`subtitles` 滤镜，能吃 ASS override 代码）与 `ffmpeg filtergraph`（只能靠滤镜参数）。凡要「一句话里多种颜色、逐字动画、精确定位」的，几乎都必须走 libass override。
> P2V 现状锚点（判断依据，全部来自 `pic2video.py`）：一条顺序 `filter_complex`（`build_graph()`）；字幕走 `subtitles` 滤镜（`ass_filter()`），生成器 `format_ass()` 只写一行 `Style: Default`；预览是 QPainter 自己画（`_draw_subtitles()`），只认全局字体/字号。

## 一句话结论

这类工具真正值钱的地方不是「能加字幕」，而是把「一句字幕 = 一个可拖拽的块」当成唯一交互单位：建块、定界、批量修、样式、导出全部围绕这个块收敛，再靠「预览与输出共用同一份 ASS」保证所见即所得。

对 P2V 的含义分两层：**交互骨架**（块、定界、批量、面板）是纯 UI，便宜；**样式系统 + 所见即所得**要先解决两件事——应用内预览是 QPainter 手画而不是 libass，`force_style` 又把字体字号钉死。这两处不改，样式只会「导出好看、预览不对」。

## 1. 全流程：一条字幕从建工程到压出画面

这类工具的流程是「媒体 → 文稿 → 时间轴（块）→ 样式 → 输出」，每段一个独立面板，任意一段可跳过。

| 阶段 | 提供什么 | P2V 现状 | 档位 |
|---|---|---|---|
| 建工程 | 自有工程文件；导入媒体（已有媒体时变为替换）；自动备份默认开启、默认 5 分钟一次 | 工程 JSON 已存 cues 与设置 | 便宜 |
| 文稿（可选） | 侧栏直接粘贴未打轴文稿；高级文本编辑器里可查找、批量断句、替换、正则替换、合并、检查每行字数 | 无文稿概念，只有已解析的 cue 列表 | 便宜 |
| 建块 | 回车插空白块（默认 2 秒）；右键插入；拖拽选区；拍打键；由标记批量生成；VAD 自动切分 | 只能从 .srt/.ass 导入 | 便宜 |
| 打轴 | 波形 + 频谱、吸附开关、拖块边缘、把入出点定到播放头、批量对齐 | 只能整块平移 | 便宜～中等 |
| 编辑 | 双击改字、多选、复制粘贴、合并切分、文字修剪、查找、重叠处理 | 无 | 便宜 |
| 样式 | 命名样式表（默认样式不可删）+ 若干小组 + 块级独立参数 + ASS 代码透传 | 只有全局字体/字号两项 | 中等 |
| 双语/翻译 | 双语稿切双轨；逐句人工翻译；批量机器翻译（按量计费） | 无 | 中等 / 贵（机器翻译） |
| 预览 | 直接用 ASS 渲染预览，与压制同一套 | QPainter 手画，与导出不一致 | 中等～贵 |
| 压制/导出 | 标准 MP4（CRF 或 ABR）；MKV 直封 ASS；专业格式与可关闭字幕流属付费特权；字幕另存 ASS/SRT/VTT/LRC/XML/PNG | 已有导出链，`format_ass` + `subtitles` 烧录 | 便宜～中等 |

两个设计决定值得记：其一，**文稿与时间轴是两条独立数据**，文稿可以晚于时间轴存在，靠「填充」把文字灌进已建好的块，所以「先打空轴、再补文字」是官方推荐路径，也是多人协作的基础。其二，**预览与输出共用 ASS**，没有第二套渲染器——这正是 P2V 缺的那一环。

## 2. 打轴：块、标记、拍打

### 2.1 标记 → 块的两级结构

标记是打轴的底层原语，块可以由标记推导出来，也可以只当视觉提示。

| 类型 | 键 | 用途 |
|---|---|---|
| 开始标记 | `,` | 标记块开始 |
| 普通标记 | `;` 或 `M` | 既可标记开始/结束，也可当视觉标记 |
| 结束标记 | `'` | 标记块结束 |

操作规则：每个时间点只允许一个标记；同种标记重复插入＝删除，插入另一种＝切换类型；标记可左右拖动，向上拖一段可快速删除。同类工具有「跳上/下一个标记」与「预览哪些区间会生成有效块」的键位。

建块判定只有一句：结束点后面紧跟开始点的区间无效，其余情况都会成块——块是「开始…结束」的有向配对，普通标记按前后类型解释。

VAD 自动切分产出的是标记而不是块，目的是让人先调标记、再一键成块，避免返工。

> 值得借鉴的抽象：P2V 现在只有 cue，没有标记。「标记 → 块」这个两级结构让「粗打轴」和「定稿」可以分开做，也让自动结果有一个可人工修正的中间态。

### 2.2 建块与定界的键位思路

- 回车在播放头插空白块，默认 2 秒（时长可在选项里改）；带修饰键则顺带填入文稿第一条内容。
- 拍打：按住一个键定开始、松开定结束，两个键交替按住即可连续建块；另有「把两块衔接点设到播放头」的合并键。
- 定界三种并存：拖块左右边缘；把入点/出点直接设到播放头；用数字键快速设「播放头穿过或右侧第一个块」的入点与「左侧第一个块」的出点，不需要先选中。
- 切分：切割工具点一下即切；另有「文字向前/向后修剪」，切分后把跨越切分点的文字挪到前/后一句，同时把两块的衔接点对齐到播放头。
- 移动：拖动整块平移、时长不变；修饰键加方向键按像素微调；多选后可按「左移整体到播放头」「右侧对齐播放头」等整体平移。
- 批量：全选、选中当前轨、选中全部空白块、框选、增选、下一个；「消除多个块之间的间隙，使其首尾相连」与「合并多块」各有一个键。

> 这套键位值得注意的不是具体字母，而是**分工**：鼠标负责「看着波形调」，键盘负责「精确设到播放头」，两者不互相替代。

### 2.3 吸附与波形对齐

吸附有开关，首选项里可设默认关闭；波形与频谱精度可调，改后需重新加载媒体；对齐主要靠「看波形 + 拖 + 吸附」，没有「对齐到音频事件」这种自动量，多人协作页把「粗轴精调」明确写成人眼读波形的工作。

### 2.4 自动切分音频（VAD）：少数离线可用的「自动」

算法是门限 + 卷积，四个参数：先定门限（高于视为语音，用于滤底噪与背景音乐），再设最短静音与最短语音时长决定粒度，最后设提前量与延长量给呼吸空间。限制写得很直白：只适用于纯人声或仅轻微背景音乐；结果只与音频特征相关、与文稿无关，不能直接填文稿。

> 这是少数「自动」但**不联网、不按量计费**的能力——对 P2V 的意义比 ASR 大得多。

### 2.5 时间码输入

把时间码栏切到编辑态后，可输入 `50` / `50s` / `1m5s` / `1h6m30s` / `+5` / `-1:20` 这类写法直接跳转，`a`/`z` 跳到当前块的起止位置。这套「一段文本解析成时间偏移」的输入比拖播放头精确得多，是硬字幕对轴的刚需。

### 2.6 批量修错位

选中块后可整组左右拖，或打开时间调整面板。它把日常错位分成六类，每类一个开关式操作：整体提前/延迟、整体压缩、整体拉伸、部分偏移、部分压缩或拉伸、混合。

这套面板说明一件事：**打轴的成本大头不是「打第一遍」，而是「改第二遍」**——整轨偏移几十毫秒、片头加了 3 秒导致全轨平移，都是常态。P2V 现在只能一句一句拖，这块是纯 UI 收益。

## 3. 块的编辑

| 能力 | 做法 | P2V 现状 |
|---|---|---|
| 改文字 | 双击块进编辑，回车确认、Esc 放弃；编辑态可试听这一句 | 无 |
| 边改边切 | 编辑框内回车＝确认并在下方新建等宽块；修饰键回车＝把光标后文字转到下方新块 | 无 |
| 改入出点 | 拖边缘、定到播放头、数字键 | 只能整体挪 |
| 多选 | 框选、增选、全选、选中当前轨、选中空白块 | 无 |
| 复制粘贴 | 复制的是块内**文字**（一行一句）；粘贴按行填入选中的块；另有「复制块到播放头」 | 无 |
| 合并 / 拆句 | 合并多块、绑定工具、切割工具、文字修剪 | 无 |
| 查找与替换 | 查找块；替换与正则替换只在文稿层做，不动时间轴 | 无 |
| 重叠 | 新建块自动防重叠；导出非编前有「定位重叠」与「一键去重」；另有实验性的对齐工具 | 无（时间轴天然不重叠） |

一个容易忽略的设计：**块 ≠ 楼层**。块可以上下挪轨，轨道既可能表示「渲染成第几行」，也可能只是图层，取决于输出模式。P2V 目前没有轨道概念，cue 是一条平铺列表。

## 4. 样式系统

### 4.1 命名样式表 + 小组 + 块级覆盖

核心事实：它的「样式」就是 ASS 的 `Style` 行，编辑器只是这张表的图形界面——因为预览与压制都交给 libass。

| 机制 | 行为 | 落到 ASS | 档位（P2V） |
|---|---|---|---|
| 样式列表 | 可增删改复制重命名；默认样式不可删；复制出的样式名自动加后缀；双击编辑 | 一行 `Style:` | 中等：`format_ass()` 要写多行 |
| 第二语言样式 | 自带一份第二语言默认样式 | 另一行 `Style:` + 不同 `Dialogue` | 中等 |
| 样式编辑器 | 上半实时预览（可改预览文字、开关视频截图与安全线），下半参数：字体、颜色、字号、粗斜下划线删除线、描边宽与色、阴影偏移与色、对齐、垂直边距、左右边距、缩放、旋转、字间距；多为「滑块 + 可输精确值」 | 对应 `Fontname`/`PrimaryColour`/`Fontsize`/`Bold`/`Outline`/`OutlineColour`/`Shadow`/`BackColour`/`Alignment`/`MarginV`/`MarginL`/`MarginR`/`ScaleX` 等 | 中等 |
| 小组 | 若干标准组 + 专用组，每组一个标识色并绑定一个样式；可设默认组；组操作含「删该组全部块」「清该组文字」「统一该组样式」「选中该组全部块」 | 本质是 `Dialogue` 的 style 列 + 颜色标签 | 便宜（P2V 的 cue 已有 `style` 字段） |
| 块级覆盖 | 块左上角出现小圆点＝没跟随小组样式，而是另指定了样式；样式数量不受小组数限制 | 同一张样式表，不同 style 名 | 便宜 |
| 独立位置 | 选中块按一个键弹出小窗，可**直接拖拽位置**，同窗还能改文字 | `\pos` / `\an` override | 中等（必须 override） |

版本细节：字号上限曾从 256 提到 540；某版起支持「矩形背景包含多行字幕」（多行共用一个背景框）；取色只取 RGB、透明度不变。

### 4.2 三种「花活」其实是 ASS 特性的直通

| 效果 | 操作 | 实现口径 |
|---|---|---|
| 打字机 | 给块设「打字机效果」，滑块百分比＝占字幕时长的比例 | ASS 逐字显现（override 动画） |
| 横向滚动 | 同一面板选「滚动字幕」，可调速与方向 | `\move` |
| 一句多样式 | 在文本里插入「样式替换」代码，指定另一套样式名 | `\r<StyleName>` |
| 进度条 + 章节 | 给标记写备注作章节标题，用自带样式控制外观，输出时另生成章节文本 | 样式 + `\pos`/`\p` 一类绘制 |
| 词汇过滤 | 工程设置里配「淡化 / 替换」规则，每个关键词一条 | 输出前替换文本，不改工程原文 |

词汇过滤有个重要限定：只对「直接输出视频或输出 ASS」有效——即它是一层**输出期变换**，工程里保留原稿。这个「原稿与输出分离」的思路值得借鉴。

### 4.3 ASS 输出模式：同一份时间轴，几种落法

它把 ASS 输出分成 A/B/C/D 四种算法：A 向下合并（默认，块之间可能互相影响，适合单语/双语）；B 保持轨道结构（块互不影响，轨道位置＝屏幕行号，最下面轨道在最后一行）；C 保持块独立（块互不影响，轨道只当图层，重叠时上面轨道盖住下面，不自动换行）；D 是「顶级块独立」，页面写着建设中。

> 对 P2V 的直接含义：**双语不需要新渲染器**，只要「两条轨道 + 两个 Style + 合适的对齐与边距」，或者干脆让轨道＝行。真正需要 override 的只有「同一句里换样式/换位置/做动画」。

### 4.4 成本真相

它的样式系统之所以便宜，是因为预览和输出都交给 libass，样式表就是 ASS。P2V 的预览是 QPainter（只读 `subtitle_font`/`subtitle_size`），导出才是 libass，所以做多样式必须二选一：

1. **预览侧补一套「ASS 样式子集 → QPainter」映射**（字体/字号/颜色/描边/阴影/对齐/边距/位置）。中等工作量，覆盖日常样式足够；`\r`、`\t`、`\move`、`\p` 不覆盖，预览里显示为纯文本，可接受但要提示。
2. **预览也走 libass**（逐帧调 ffmpeg 或绑定 libass）。所见即所得最彻底，但绑定 libass 是新依赖（贵），且 `subtitles` 滤镜是烧进画面的，做不了「预览关字幕」。

不管走哪条，都得先改两处：`ass_filter()` 里的 `force_style` 会把样式表里的字体字号盖掉，做多样式必须去掉；`_ass_escape()` 把花括号转义，写 override 前必须先让它放行合法代码块。

## 5. 双语与翻译

| 能力 | 做法 | 依赖 |
|---|---|---|
| 双语稿切双轨 | 要求 TXT、两种语言隔行、允许空行、去空行后行数为偶数；导入建块后「切分为双轨」，第二语言分配到专用组，可各给样式 | 纯本地 |
| 两稿分开做 | 先导入源语言打轴，为所有块建副本，再导入第二语言稿，逐行填充副本 | 纯本地 |
| 逐句人工翻译 | 翻译器：上原文下译文，均显示字数；回车跳下一句；常用词汇区可拖入并一键插入；另有上一句/下一句、在线查词、在线翻译整句 | 查词/整句翻译需联网 |
| 批量机器翻译 | 选组、源语言与目标语言，软件先估算所需费用再确认；某版起支持只处理选中块 | 联网 + 按量计费 |
| 其他语言处理 | 汉字转拼音（带调号）、自动换行工具（单词型不切词 / 连续型按长度切） | 纯本地 |

一个坑（官方 FAQ 记的）：双行字幕导出非编 XML 会变单行，因为其样式不适用于该序列，正确做法是分轨导出。对 P2V 是提醒：双语一旦靠「一行里塞两行字」实现，任何把文本当纯文本处理的下游都会塌，双轨/双块才稳。

## 6. 依赖边界：哪些必须联网、登录或花钱

P2V 是离线优先、无账号的桌面工具，所以这一节直接决定「做不做」。

| 功能 | 依赖 | 离线等价物 |
|---|---|---|
| 建块、打轴、波形、样式、特效、双语切分、拼音、自动换行、词汇过滤、压制、导出 | **纯本地** | 无差异 |
| 自动切分音频（VAD） | **纯本地** | 门限+卷积四参数 |
| 单句语音识别 / 整段转写 | 联网 + 登录 + 按量计费（识别失败不计费，重复识别重复扣费；转写任务一旦创建不可取消） | 自建 whisper.cpp（模型体积大，贵）或不做 |
| 自动打轴（AI） | 登录 + 余额 | 只有 VAD（精度不同） |
| 语音合成 | 按量计费（部分引擎还需密钥） | P2V 已走 Edge/Gemini/OpenAI 兼容（`tts_engine.py`） |
| 批量机器翻译 | 联网 + 按量计费 | 无（本地翻译模型体积/质量都不划算） |
| 高级压制 / 专业格式 / 软字幕导出 | 登录 + 激活特权 | ffmpeg 直接给（P2V 天然免费） |
| 单机离线买断版 | 一次性付费，且联网类功能不可用 | P2V 全面覆盖其离线部分 |

**结论**：这类工具的功能面里，**打轴/样式/双语/导出这些骨架全是离线的**，联网项集中在识别、翻译、合成三件事，且都按量计费。所以 P2V 借鉴骨架没有依赖风险；一旦要碰 ASR/翻译，就必须自己做本地模型或接受联网，不能假装是「免费离线功能」。

## 7. 可移植性判断（逐条）

| # | 机制 | 档 | 理由 | P2V 落点 | 渲染侧 |
|---|---|---|---|---|---|
| 1 | 一句 = 一个块，块带入出点与样式 | 便宜 | cue 已经是 dict，加键即随工程 JSON 持久化 | `_cue()`、`to_doc()` | 无 |
| 2 | 回车插空白块（默认 2 秒）、带修饰键带文稿 | 便宜 | 纯 UI 事件 + 一次 append | 字幕面板 / 时间线 | 无 |
| 3 | 拖边缘改入出点、把端点定到播放头 | 便宜 | 只差一个 `set_cue_end`（现在只有 `set_cue_start`） | `Project.set_cue_start` 附近 | 无 |
| 4 | 吸附开关 + 候选点扩展（播放头/块边界/音频头尾） | 便宜 | 候选函数与波形缓存都现成 | `snap_value` / `snap_candidates` | 无 |
| 5 | 时间码解析（`1h6m30s`、`+5`） | 便宜 | 一个纯函数 + 输入框 | 新 | 无 |
| 6 | 标记 → 块 + 建块规则 | 便宜 | 新数组 + 时间线绘制；规则就是「开始…结束」配对 | 新 | 无 |
| 7 | 拍打建块 | 便宜 | 按住/松开的计时事件；精度取决于预览时钟（未验证抖动） | 新 | 无 |
| 8 | 多选 + 批量平移/对齐/消隙 | 便宜 | 全是对 cue 数组的批量变换 | `on_subtitle_move()` 泛化 | 无 |
| 9 | 批量调整面板（六类错位） | 便宜 | 同上，加一个对话框 | 新 | 无 |
| 10 | 命名样式表（多 `Style:` 行）+ 每块 `style` 字段 | 中等 | `format_ass()` 现在只写一行，字段名已透传 | `format_ass()` | 生成侧 |
| 11 | 去掉/收窄 `force_style`，让样式表生效 | 中等 | 不改就永远只有一个字体字号 | `ass_filter()` | 生成侧 |
| 12 | 样式编辑器 + 小组颜色 | 中等 | 参数面板是体力活，但要与 ASS 字段一一对应 | UI + `format_ass()` | 生成侧 |
| 13 | 应用内预览与导出样式一致 | 中等 | 要在 QPainter 里实现 ASS 样式子集 | `_draw_subtitles()` | **预览侧** |
| 14 | 独立位置 / 一句多样式 | 中等 | 必须 override，且要放行花括号 | `_ass_escape()` | **libass override** |
| 15 | 打字机 / 横向滚动 | 中等 | `\t`、`\move` 是 libass 原生；预览要么做简版要么不显示 | 同上 | **libass override** |
| 16 | 双语双轨 | 中等 | 两条 `Dialogue` 不同 Style，或轨道＝行；不用新渲染器 | `format_ass()` + cue 的 track/style | 生成侧 |
| 17 | 进度条 + 章节 | 中等 | 样式 + 绘制指令，再加一个纯文本旁产物 | 生成侧 | **libass override** |
| 18 | 词汇过滤 | 便宜 | 只在烧录前改文本，不影响工程原文 | 写盘前 | 生成侧 |
| 19 | 额外字幕格式（VTT / LRC / MicroDVD / Excel） | 便宜 | 全是文本序列化 | 与 `cues_srt` 并列 | 无 |
| 20 | MKV 直封 ASS、可关闭字幕流 | 便宜 | `-c:s copy` / `-c:s ass` + 封装参数 | 导出命令 | 封装 |
| 21 | 带 Alpha 的纯字幕 MOV、PNG 序列 | 中等 | 要逐句渲染成图 | 新导出分支 | **libass 渲染** |
| 22 | VAD 自动切分（产出标记） | 中等 | 算法几十行 + 复用已有峰值；纯离线 | `audio_peaks` | 无 |
| 23 | 自动备份 / 撤销重做 | 便宜 | 撤销已有 | 已有 | 无 |
| 24 | 章节文本等旁产物 | 便宜 | 纯文件旁产物 | 导出链 | 无 |
| 25 | AI 打轴 / 识别 / 转写 / 机器翻译 / 云端合成 | 贵 | 联网 + 账号 + 按量计费；P2V 无账号体系 | — | 云 |
| 26 | 导出到多种非编私有 XML | 贵 | 每种一套 schema，维护成本高，且 P2V 定位是成片 | — | 无 |
| 27 | 工程文件交换协作 | 贵 | 要定义可合并的工程格式与冲突规则 | — | 无 |

**只在 libass 里成立**：一句多样式、独立位置、打字机/滚动、进度条绘制、带 Alpha 的纯字幕 MOV。P2V 已经走 `ass_filter` → `subtitles` 这条路，所以这些**不需要新依赖**，只要生成正确的 ASS 文本。

**只能改 ffmpeg 命令**：封装与流选择、烧录开关、逐句渲图。这些不涉及 ASS 内容。

**必须绕开的位置**：`force_style`（会盖掉样式表）与 `_ass_escape`（会吃掉 override）——这两处不先处理，override 类方案都会「看着写了但没生效」。

## 8. 值得借鉴的 10 条

| # | 借鉴什么 | 为什么 | 档 |
|---|---|---|---|
| 1 | 一句 = 一个块，带入出点、文字、样式、轨道；回车插 2 秒空白块 | 所有编辑动作收敛到一个对象上，是后续功能的公共底座 | 便宜 |
| 2 | 拖边缘改入出点 + 端点一键定到播放头 | 打轴大部分时间花在定界，鼠标拖与键盘定界必须并存 | 便宜 |
| 3 | 时间码文本输入（`1h6m30s` / `+5`） | 精修几十毫秒靠拖是自虐，文本输入才可复现、可批量 | 便宜 |
| 4 | 吸附开关 + 候选点含播放头/块边界/音频头尾 | P2V 已有 `snap_candidates`，只差把 cue 边界塞进去 | 便宜 |
| 5 | 标记 → 块的两级结构 | 「先粗打轴再定稿」，也让自动结果有可人工修正的中间态 | 便宜 |
| 6 | 拍打建块（跟播放计时，而非事后拖） | 听写场景手感更顺，比「先插块再拖」少一半操作 | 便宜 |
| 7 | 多选批量：整体平移/压缩/拉伸、消隙、联动长度 | 返工大头是整轨偏移，一次性投入长期回本 | 便宜 |
| 8 | 命名样式表 + 每块 `style` 字段 | cue 已有 `style` 键，只缺 `format_ass()` 写多行样式；不加依赖就能做多样式 | 中等 |
| 9 | 双语双轨 | 刚需，且不需要新渲染器（两条 Dialogue 或轨道＝行） | 中等 |
| 10 | 文稿 ↔ 块 的文本流转（导出块文本、按行填充、合并、并入下一行） | 翻译、重排、错句修复全靠这套 | 便宜 |

## 9. 明确不打算做的 5 条

| # | 不做什么 | 为什么 |
|---|---|---|
| 1 | 按量计费 + 账号登录 + 特权激活 | P2V 的口碑建立在「离线、无账号」；把核心能力挂到余额上等于换产品 |
| 2 | AI 自动打轴 / 语音识别 / 整段转写 / 批量机器翻译 | 全部联网付费，且识别后仍要人工校对，收益成本比在 P2V 不划算 |
| 3 | 导出到多种非编私有 XML | 每套 schema 都要长期跟版本；P2V 的出口是成片 |
| 4 | 进度条特效 / 词汇过滤 / 卡拉OK 逐字上色 | 靠 override 堆出来的特例样式，P2V 没有这类需求来源 |
| 5 | 四种 ASS 输出模式全做 | 对方自己也没收敛（有模式仍在建设中）；P2V 固定一种即可，别把多选暴露给用户 |
